## The story in my own words

Hookline acts as a central post office and event relayer between servers. In typical web applications, clients are human users on browsers or mobile apps. In Hookline, the clients are other companies' servers (like Shopify or Stripe) dropping off letters (event payloads like `order.paid`).

Hookline accepts those letters across the counter, records them into a central persistent ledger (PostgreSQL), and delegates delivery couriers to send the messages across town to the recipient servers (customer webhook endpoints). When delivering, Hookline flips roles and becomes the HTTP client. The post office guarantees delivery, retries when recipient doors are closed or slow, and ensures one customer's flood of letters doesn't starve everyone else.

## The pain

There was no previous version of Hookline. The pain is starting with a blank canvas and needing to understand the full machine-to-machine journey of a network request before writing any server code. You cannot debug or scale a system you cannot picture.

## The first principle

A backend is a long-running OS process listening on a port, guarding state the client cannot be trusted with (the trust boundary) and coordinating work across systems.

Every HTTP request travels through distinct physical and protocol layers:
1. **DNS (UDP 53):** Translates human domain names into IP addresses.
2. **TCP Handshake:** 3-way handshake (`SYN` → `SYN-ACK` → `ACK`) establishing a reliable, ordered byte stream.
3. **TLS 1.3 Handshake:** Cryptographic key exchange and server certificate verification establishing an encrypted tunnel.
4. **Reverse Proxy (The Guard):** Sits in front of our backend to terminate TLS (decrypt HTTPS to raw HTTP), absorb slowloris/DDoS traffic, buffer slow clients, and distribute load across backend instances.
5. **Application Process:** Our Go process receives the raw HTTP stream, routes it, executes domain logic, and writes to disk.
6. **Persistence (The True Bottleneck):** Disk I/O and unindexed database queries are where ~80%+ of backend latency lives in production; in-memory code takes microseconds, network transit takes milliseconds, and slow disk I/O dominates.

## Break-it experiment

We ran `curl -v https://api.github.com` to observe the invisible network hops beneath a standard HTTP request:

```text
* Host api.github.com:443 was resolved.
* IPv4: 140.82.121.6                       <-- [Phase 1: DNS Resolution]
*   Trying 140.82.121.6:443...
* Connected to api.github.com (140.82.121.6) port 443 <-- [Phase 2: TCP 3-Way Handshake]
* ALPN: curl offers h2,http/1.1
* TLSv1.3 (OUT), TLS handshake, Client hello (1):    <-- [Phase 3: TLS 1.3 Handshake]
* TLSv1.3 (IN), TLS handshake, Server hello (2):
* TLSv1.3 (IN), TLS handshake, Certificate (11):
* TLSv1.3 (IN), TLS handshake, CERT verify (15):
* TLSv1.3 (IN), TLS handshake, Finished (20):
* SSL connection using TLSv1.3 / TLS_AES_128_GCM_SHA256
* ALPN: server accepted h2
> GET / HTTP/2                              <-- [Phase 4: HTTP Request Headers]
> Host: api.github.com
> User-Agent: curl/8.5.0
> Accept: */*
< HTTP/2 200                               <-- [Phase 5: HTTP Response Headers]
< server: github.com
< content-type: application/json; charset=utf-8
< content-length: 2396
{ "current_user_url": ... }                <-- [Phase 6: Response Body]
* Connection #0 to host api.github.com left intact  <-- [Keep-Alive / Socket Reusable]
```

**What it proves:** Even a trivial request involves name resolution, socket handshakes, and cryptographic negotiation before a single byte of HTTP data is transferred. Subsequent requests reuse the connection via keep-alive.

## What surprised me

- How much work happens before the server even sees the request (DNS, TCP, TLS).
- How Go compiles directly to machine code as a single standalone executable without needing thousands of files in `node_modules` or the heavy Google V8 runtime.
- The realization that in webhooks, Hookline is the HTTP client calling third-party customer servers, making timeouts, worker queues, and isolation critical to avoid server starvation.
