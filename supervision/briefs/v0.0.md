# Brief v0.0 — Orientation

**Videos:** 1. Roadmap for backend from first principles · 2. Walk the path of a true backend engineer · 3. What is a backend, how do they work and why do we need them? · 4. Benefits of learning backend engineering from first principles
**Branch:** `version/v0.0-orientation`
**Roadmap section:** `ROADMAP.md` → v0.0

## Goal in one sentence
The learner can trace one request from a client to Hookline and back, naming every hop, and knows what Hookline is and why it's built this way.

## Must teach
1. **What a backend is:** a long-running process listening on a port; it holds state the client can't be trusted with and coordinates other systems.
2. **The request journey:** DNS → TCP handshake → TLS → (load balancer / reverse proxy) → process → database → response. Where latency and failure live at each hop.
3. **Hookline's job:** what a webhook is, who sends and receives, why delivery is hard (the other side is slow, down or hostile). Use the post-office story.
4. **The method:** versions driven by pain, first principles over frameworks, evidence per version (log, ADR, break-it, tag).

## Likely misconceptions to probe
- "The backend is the API." (The API is one interface; the backend also includes workers, storage, and the work no one calls directly.)
- "DNS/TLS happen once per request" vs connection reuse (keep-alive is introduced properly in v0.1; just plant the question).
- "A webhook is the same as an API call." (Direction is reversed: the provider calls the customer.)

## Check questions
1. You type a URL and press Enter. Name every step until the first byte of the response arrives, and say which one usually costs the most time.
2. In a webhook, who is the client and who is the server? Why does that make delivery harder than serving an API?
3. Why does this project start with the standard library instead of a framework like Gin or Echo?

## Teaching notes
- Start with the story, then the `curl -v https://api.github.com` break-it: annotate DNS, TCP connect, TLS handshake, request headers, response headers. Let the learner annotate first; correct second.
- Keep v0.0 short (one or two sessions). No HTTP server code yet beyond a startup print line.
- ADR-0001 (Use Go) should list at least one real alternative with honest trade-offs. Don't let it be a one-liner.

## Out of scope
HTTP internals (v0.1), routing (v0.2), databases, Docker services. `docker-compose.yml` is a placeholder only.
